# Grill

Inspect the assignment, existing architecture, plan, progress, and relevant
code before asking questions. Facts the repository or a bounded experiment
can answer are investigation work, not questions for the human.

Ask one consequential question at a time, with a recommendation and the
tradeoff in plain language. Use the available user-input tool when present.
Prioritize intended behavior, scope, privacy, failure/timeout behavior, and
what observable result proves success. Continue independent inspection while
waiting. Never treat elapsed time as an answer to a required product choice.

Stop when the important choices are clear; do not interview indefinitely or
force an ADR/glossary for ordinary terminology. Produce a concise acceptance
contract, unresolved decisions, and the smallest implementation plan. Record
lasting decisions in the existing architecture/plan only once agreed. An
explicit request for interrogation is not permission to implement the feature.
